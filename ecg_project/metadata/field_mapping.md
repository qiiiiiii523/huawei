# 字段说明与单位约定

本文档说明第一阶段索引、配对和后续统一数据处理中使用的字段含义。原始数据目录保持只读，原始字段不会被覆盖。

## `externalid` 与 `subject_id`

- `externalid` 是手表导出文件中的原始受试者标识，必须原样保留。
- `subject_id` 是项目内部统一后的受试者标识，用于跨文件、跨设备索引和 subject-level 划分。
- `subject_id` 不能覆盖或替代 `externalid`。无法可靠统一的 ID 保留原值，并进入 `id_mapping_review.csv`，不进行猜测。

## `groupid`

`groupid` 是手表一次采集组的标识。手表 ECG 与 PPG 优先使用相同 `groupid` 配对；它用于确认同一组采集，不用于替代跨设备的统一 `subject_id`。

## `record_id`

`record_id` 是项目内部生成的唯一原始记录编号。它用于在 manifest、QC、配对表和报告之间稳定引用一条记录；它不是原始设备 ID，也不代表受试者身份。

## 手表 ECG 与 PPG 配对

手表 ECG/PPG 首先从各自原始字段提取 `externalid`，再保留 `groupid`。同一受试者的 ECG 与 PPG 优先按相同 `groupid` 配对；没有可靠 `groupid` 关系时不猜测。PPG 本阶段用于索引和覆盖检查，第一版暂不输入模型。

## d6 与 d12 配对

- 心电图机 d6/d12 的受试者编号从 XML 文件名或 XML 内容提取 HNU 编号。
- 跨设备配对优先使用统一 `subject_id`。
- d6 与 d12 不要求绝对时间戳完全相同，因为两者可能先后采集。
- 同一受试者存在多个候选 d6 或 d12 时不自动选择，标记 `review`。
- 无对应 d12 时标记 `unmatched`；只有确定关系才标记 `paired`。

## 体脂秤被试 ID 与 `subject_id`

体脂秤 CSV 文件头中的“被试ID”是体脂秤侧的原始受试者标识。项目从该字段提取并规范化为 `subject_id`，但保留原始字段。当前体脂秤 d6 到 d12 的 ID 配对已按 exact `subject_id` 完成。

体脂秤六导联映射已确认：通道 1、2、9、10、11、12 分别对应 I、II、III、aVR、aVL、aVF；固定排列为 `I, II, III, aVR, aVL, aVF`。

## 原始采样率与模型采样率

- 原始采样率是设备文件实际记录的采样率，例如体脂秤为 500 Hz、机器 d6/d12 为 1000 Hz、手表 ECG 为 10 Hz、PPG 为 100 Hz。
- 模型采样率是统一输入模型前的目标采样率，当前 ECG 规范暂定为 500 Hz。
- 两者不同并不表示原始数据错误；后续预处理阶段才执行重采样。

## 原始单位与模型单位

- 原始单位来自设备文件或元数据，例如体脂秤为 mV，机器 d6/d12 为 uV，acceleration 为 g。
- ECG 模型内部统一使用 μV。
- 体脂秤后续预处理需要执行 `mV × 1000 -> μV`；本阶段不修改原始 CSV。
- 比赛最终输出采样率仍为 `TBD`，不得根据当前模型采样率进行猜测。
