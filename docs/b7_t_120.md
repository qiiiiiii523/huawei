# B7-T-120：保留P/Q，继续适配完整120秒华为记录

本分支从B7-T-compact@b1a4e23独立创建。原工作树及服务器40秒实验不变；必须使用独立服务器工作树，不能把本分支pull到仍在训练40秒模型的目录。模型本体model.py不变，参数量、8入7出接口、干净I、II权重5均保留。

## 路线与规则

```
P10 → A40 → A120
P10 → Q40 → B40 → B120
```

不重新训练P/Q，不延长公开数据，不重建缓存。使用对应A40/B40的最佳EMA初始化新阶段；模型及冻结尺度必须一致，Huawei manifest和逐文件hash也必须与40秒源权重一致。源代码hash允许因本120秒扩展而不同，源40秒checkpoint/config/完成状态会另外审计。新阶段重置AdamW、步数和EMA计数；初始化EMA数值等于源EMA。之后中断用新阶段last恢复AdamW/EMA/RNG和步数。

| 项目 | 设置 |
|---|---|
| 训练输入/输出 | 原始连续120秒，500Hz，60000点；完整I+七通道状态 |
| 窗口 | 必须真实完整60000点；不随机裁40秒、不补齐、不采样边界窗口 |
| FM/MAE | 全120秒的有效导联/位置 |
| PCC | 中央15～105秒，90秒；下标7500:52500 |
| II权重 | 5，其余六个生成导联1；最终评分不乘5 |
| 默认batch | 4；不是沿用40秒的32 |
| 更新 | A120/B120各新增1000步，学习率1e-5，AdamW/EMA .999/clip1 |
| 保存 | 每500步原子保存last；训练每50步输出进度 |
| 全量验证 | 跳过初始和中途，结束时评估最终EMA；K16、Heun16 |
| 并发 | 本入口串行，最多1个训练/评估子进程；不协调别的总控 |
| 验证执行batch | 默认4个ODE轨迹，不是K=4；K保持16 |

120秒训练batch4的样本/时间预算不同于40秒batch32；这些是继续适配实验，不是等预算的架构消融。尚未实测CUDA容量，不能保证batch4在任何共享GPU上都够用。首次启动看实际训练显存；要改batch或更新预算，应在新输出目录启动，不能改已运行的配置强行resume。

## 自动比较的三个推理模式

| 输出名 | 输入/生成 | 保留区域 | 120秒记录的窗口数 |
|---|---|---|---:|
| full120 | 120秒 | 全120秒 | 1 |
| window40_core10 | 40秒 | 中央10秒 | 12 |
| window40_core20 | 40秒 | 中央20秒 | 6 |

同一阶段的三种方式严格使用同一EMA、固定seed42、K16/Heun16、固定QC/患者划分/尺度及完整记录评分。40秒模式在记录首尾继续使用既有clamp补边；完整120秒模式不补边。推理40秒只能读取对应40秒I，不会同时获得完整120秒条件。

full120直接复用该阶段成功的最终评估，核验检查点和数据身份，不再重复生成一次。另两种模式分别完整评估，保存逐记录逐导联结果；中断重启只补缺失的比较结果。best_r.pt代表最终EMA在full120下的r，comparison/completed.json另存各推理r和最佳推理模式，不能把两者混作同一字段。不会用测试集选模式。

验证会持续打印scanned/total、scored_pairs、elapsed_seconds和estimated_remaining_seconds。ETA是按已扫描记录估计，不是保证。checkpoint_history另记录CUDA allocated/reserved累计峰值（从进程启动累计，包含已发生训练和验证；CPU为null）。

在新tmux内，以下示例选择1940万结构：

```bash
conda activate BioFlow
cd /home/qht/huawei_B7_T_120
mkdir -p results/B7-T-120/g6_19m/seed42
set -o pipefail
python -u -m baselines.B7.adapt120 \
  --preset g6_19m \
  --source-run /home/qht/huawei_B7_T_compact/results/B7-T-compact-suite/g6_19m/seed42 \

  --output results/B7-T-120/g6_19m/seed42 \
  --gpu 1 --batch-size 4 --eval-batch-size 4 --updates 1000 \
  2>&1 | tee -a results/B7-T-120/g6_19m/seed42/launcher.log
```

入口默认等待所选源run的A40、B40都完成，才开始120秒训练。源阶段失败/blocked会报错，不会伪造完成。训练A120后比较三种推理，再训练B120并比较；某路线失败会记录并继续另一条独立路线。要不等待而检查失败，可加--no-wait-for-source。仅做A或B可用--routes A/B；这些启动参数均锁在本次运行计划里。

只看计划可加--dry-run，不创建训练权重。中断后使用相同命令即可恢复，不能重新从源权重覆盖已有新阶段。若source-run里的best/配置/数据被更改，会拒绝恢复。

支持的源结构：

| --preset | --source-run |

preset和源模型必须匹配；输出目录也要按结构分别命名。当前入口只限制本实验一个子进程，不会暂停其他40秒训练。若同时有其他模型占用同卡，需先确认显存。不要把同一张GPU的“每个总控1个”当作全GPU总共1个。

```bash

  --checkpoint "$RUN/A120/best_r.pt" --anchor /path/to/visible_I_uV.npy \
```
