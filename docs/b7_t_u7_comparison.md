# B7-T-compact 与 B7-U7-large 的非架构核查

核查日期：2026-10-24。U7参考本地B7-U7-large@7d0d076的M2/M3入口，而非已废弃的152通道batch实验。未修改U7工作树，也未操作服务器训练。

| 项目 | 核查结果 |
|---|---|
| 原始输入与导联 | 均为干净I+七通道FM状态，生成II及V1～V6；I复制、四肢体导联公式恢复 |
| 数据与窗口 | data.py、huawei_index.py相同；公开10秒，长窗40秒，PCC中央15～25秒，FM/MAE全窗有效区 |
| 训练预算 | 两边各组P batch64×10000，Q/A/B batch32×1000；学习率1e-4/1e-5、AdamW、EMA .999、clip 1、seed42一致 |
| 损失 | losses.py逐文本一致，MAE权重1、PCC权重.1、II权重5一致 |
| 数据抽样 | balanced_indices函数AST一致，按来源/患者/记录均衡抽样 |
| 采样与评分 | keyed_noise、integrate、pearson、aggregate函数AST一致，K16/Heun16、固定key、中央10秒拼接、QC及整记录评分保留 |
| 验证安排 | 两边所有阶段均只评估最终EMA，无初始/中途全量验证；配置字段表达不同，行为一致 |
| 保存与恢复 | 每500步保存last，包含模型/EMA/优化器/RNG/步数；验证前先保存、验证中断补评；不使用旧B5权重 |
| 计算批量 | U7记录batch4、ODE chunk16；T记录/窗口打包批量上限32、ODE轨迹上限32，K仍为16；实现不同，不应直接拷贝配置字段 |
| PTB扫描 | 都排除根目录副本，只保留patient数字目录；T额外写审计信息，无患者划分规则冲突 |

发现并修复：T复用缓存现在也优先选择ptb_recovery/data/manifest.json，不存在再使用data/ptb40；仍核对manifest、尺度及逐文件hash。最终完成核验增加best_r.pt步数必须等于最终步数的检查，防止误用中间权重。

并发入口新增`python -m baselines.B7.compact_suite`：一个总控调度两组八阶段，默认全局最多2个训练进程，CLI仅允许1/2。训练进程在执行末尾验证时仍占一个槽位。两组P先启动，后续按各自依赖排队；Q失败不影响另一组，A失败不影响本组Q→B。U7当前默认不限制并发，可能出现4个长窗进程，本次没有照搬此默认值。

原单组compact入口仍默认1进程，供单独训练使用。新总控默认使用另一个suite输出根目录，禁止同时用不同总控管理相同阶段目录；旧的1506万B7-T工作树不变。已启动的旧compact配置不能直接采用新代码续训，严格身份检查会拒绝；新实验应在启动前更新。

108项本地CPU测试通过，包含全局两槽真实调度循环模拟、八阶段依赖、失败隔离、修复PTB缓存优先、短测失败阻止启动、最终权重步数检查，以及原有EMA/优化器/RNG恢复验证。未实测服务器CUDA显存或新模型r。GPU短测仅覆盖训练；35GiB是单进程预算，不是两个并发进程的合计上限，也不限制其他实验。
