# B5目标导联QC验证协议

## 已确认的问题和修改

原B5验证接口未返回目标导联质量mask，评分函数因而把明确标差的导联也计入r和RMSE。已修改B5读取main现有设备QC数据中的`target_lead_mask`，逐导联排除对应目标。**只排除某条记录的坏导联，不删除整条记录，也不置零。**

例如某条记录仅V4标差，则该记录的V4不参与r和RMSE；V3、V5及其他正常导联仍参与。质量依据来自设备QC文件，不由模型分数决定。验证目标、输出波形、原始μV和120秒拼接保持原样。

## 评分与选模

- 每个导联先保留该导联正常的目标记录，重复配对在目标内平均，目标间等权。II—V6的r再按导联等权汇总。
- RMSE排除坏导联的平方误差，也排除它对应的样本数。Task2加分仍仅使用V1—V6。
- Task2机器和体脂秤分别计算后1:1汇总。各设备RMSE先换算加分，再取平均。
- 总分仍为`50 × (0.5r1 + 0.5r2) + 平均加分`，最高60分；本次没有修改公式。
- `best.pt`按QC总分、`best_r.pt`按QC主相关性、`best_bonus.pt`按QC加分保存，`last.pt`保留最新状态。同一套QC协议用于周期验证和独立validate。
- 每个必评分导联至少要有一个正常目标，且至少一个正常目标的r有定义；否则报错，不自行减少评分导联。

新评估协议：`machine_body_equal_weight_target_record_qc_score_v3`。
新总分协议：`correlation50_bonus10_target_record_qc_v3`。
新选模协议：`b5-total-correlation-bonus-target-qc-v2`。

共享接口已先提交main，再同步到B5。main中的默认调用仍完整导联评分，其他模型需显式传mask才启用QC。此协议用于本地可靠导联验证，不能据此声称主办方测试成绩必然提高；新旧验证分数不能直接混比。

## 训练和测试

**网络、条件、训练损失、学习率、预算、周期验证频率均未改变。周期验证和最终生成仍为Heun16/K16。**

QC mask仅用于评分，不是新增模型条件，也不需要推理时知道真实目标。测试时仍只输入同步I及已有的人口学信息，模型输出全部12导联。训练已有的质量mask监督逻辑保持原样。

旧checkpoint的网络权重仍兼容预测或作为新运行初始化。但旧`last.pt`中的best记录来自旧评分范围，不能直接用`--resume`接着新协议选模；程序会明确拒绝，不会混用两套分数。新训练应使用新输出目录，微调可继续从公开预训练权重初始化。公开预训练本身不因本次华为验证QC修改而必须重训。

现有配置仍指向原输出目录。开始新的QC运行前，应复制实验配置并给`paths.output_dir`设置新的目录；不覆盖已有训练。配置的其余参数保持一致。

旧预测CPU重算、四份候选统一评估及S50/S50-F组合重评，见 [已有结果QC重评](b5_saved_candidates_qc_reassessment.md)。该工具不运行训练、不覆盖旧权重。

## 导出的核对信息

每次验证保存：

- `task1/target_quality_mask.npy`、`task2/target_quality_mask.npy`：按窗口顺序排列的`[N,12]`正常导联mask。
- `window_metadata.csv`：额外保存每条窗口的`target_lead_mask`。
- `lead_metrics.csv`：每导联r、有效目标数、有效样本数、QC排除目标/配对数。Task2按设备分别列出。
- `overall_metrics.csv`：标明QC协议、mask已应用、排除计数、mask和QC源文件摘要。
- `competition_score.csv`、checkpoint、初始化记录：标明新协议。

同一目标在不同窗口、不同配对和两设备中必须使用相同mask，矛盾时直接报错。报告的整条记录总数仍包含保留的记录；各导联有效目标数可能不同。
