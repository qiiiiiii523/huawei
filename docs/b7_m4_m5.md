# B7-M4-M5：宽度与瓶颈深度组合，固定预算训练

独立分支`B7-M4-M5`，基于`B7-U7-large`的`7d0d076`创建。
仅新实验使用此checkout，不在正在训练M2/M3的目录切分支或拉取本分支代码。
本分支入口是`run_b7_m45.py`；继承的M2/M3入口仅保留历史功能。

## 两组模型

| 设置 | M4 | M5 |
|---|---|---|
| U-Net宽度 | 128/256/512 | 128/256/512 |
| 瓶颈残差块 | 6 | 8 |
| dilation | 1/2/4/8/16/32 | 1/2/4/8/16/32/1/2 |
| 实测参数量（CPU实例化） | 14,685,087 | 18,233,247 |

完整干净I直接拼接七通道FM状态（8通道输入），I不加噪，无独立I编码器或旧CNN分支。
仅学习II、V1–V6的七通道速度；复制I并按肢体导联关系恢复另外四条，最终输出12导联。
500Hz；长窗输入输出完整40秒，FM/MAE使用整窗真实有效区，PCC只用中央15–25秒；
真实10秒公开阶段使用整段10秒PCC，不拼接重复短记录冒充长窗。
loss仍为FM+MAE+0.1×PCC，II训练权重5，最终评分不加II权重。
年龄/性别等metadata条件、固定QC和原完整记录评分规则保留。

## 固定训练预算与权重选择

| 阶段 | 数据 | batch | 更新数 | 学习率 | 全量验证 |
|---|---|---:|---:|---:|---|
| P | PTB-XL+Chapman真实10秒 | 64 | **20000** | 1e-4 | 只在20000步一次 |
| Q | PTBDB真实长记录40秒窗 | 32 | 1000 | 1e-5 | 只在1000步一次 |
| A/B | 华为40秒窗，各自独立 | 32 | 各1000 | 1e-5 | 各在1000步一次 |

AdamW weight_decay=.01，EMA=.999，gradient_clip=1，seed42。
两组各自随机初始化P，无B5/M2/M3权重迁移；随后P→A、P→Q→B。
没有初始或中途全量验证。每500步保存`last.pt`，不触发评估。
阶段末以EMA做K16、Heun16验证（record batch4、ODE chunk16），成功后才启动下游。
最终的`best_r.pt`/`best.pt`仅为最后一步EMA兼容文件名，不是挑选中间最优权重。
每组四次阶段末验证；测试集不参与配置选择。
更高容量和更多步数不保证公开/华为r更高，且训练时间不保证与M2/M3相同。

## 缓存、并发和恢复

复用旧`/home/qht/huawei_B7/results/B7/auto_seed42`：
`data/public10`、`data/huawei`，PTB优先`ptb_recovery/data`，否则`data/ptb40`。
不重新prepare、不复制波形缓存，沿用训练集尺度、患者划分和QC。启动检查和续训hash核验
仍会读取缓存数据；新模型的最终验证预测/分数必须重新计算。

明确指定`--gpu-m4`和`--gpu-m5`。默认整个套件最多2个进程，同一GPU最多1个；
不同卡的M4/M5可以并行，每组通常P→A→Q→B，同组不让A和Q挤同一张卡。
此限制仅管理本套件，不控制其他用户或旧实验的任务。
`--max-train 0 --max-per-gpu 0`可取消限制；没有GPU短测或40 GiB停止阈值。
M4长窗完整进程可按约35–45 GiB、M5约40–50 GiB粗略规划，均未实测CUDA，不能保证峰值。

同一命令可恢复：原目录的`last.pt`恢复模型、AdamW、EMA、随机状态和步数；完成阶段核验后跳过。
如果第一次更新OOM、仅有`initial.pt`，新入口严格核验代码/配置/数据身份与第0步状态后，
从真实初始状态创建恢复点，原始`initial.pt`不修改。不盲目覆盖或删除部分目录。
最终验证前保存checkpoint，验证中断会补完它，不重新更新最后一步参数。
失败只阻塞依赖它的下游：A失败不影响Q→B；Q失败阻塞B；另一模型独立继续。

更换GPU或并发数属于运行设置：先停止这个总控并等待子进程退出，再用**同一输出目录、
同一models列表**和新GPU编号启动即可，不需要改模型配置或伪造指纹。其他代码、配置、
数据路径与文件变化仍会拒绝恢复。不要同时让两个总控管理同一个实验输出。
如果要只做一组，首次启动就指定`--models M4`或`--models M5`并使用独立输出目录，
不要在进行中的双模型套件中改models列表。

## 服务器启动

先将本地`B7-M4-M5`分支推送Gitee。在服务器独立创建checkout，以下假设remote名为gitee：

```bash
cd /home/qht/huawei_B7
git fetch gitee B7-M4-M5
git worktree add /home/qht/huawei_B7_M45 gitee/B7-M4-M5
tmux new -s b7_m45
```

如果checkout已经存在，进入该新目录fetch并ff-only更新即可；不要在活动的旧B7目录换分支。
GPU0/1仅为命令示例，执行前根据当前空闲显存选择；本地完成代码不等于已启动服务器训练。
在新tmux执行：

```bash
conda activate BioFlow
cd /home/qht/huawei_B7_M45
mkdir -p results/B7-M4-M5
set -o pipefail
python -u scripts/run_b7_m45.py \
  --gpu-m4 0 --gpu-m5 1 \
  --reuse-data-from /home/qht/huawei_B7/results/B7/auto_seed42 \
  --output results/B7-M4-M5 \
  2>&1 | tee -a results/B7-M4-M5/launcher.log
```

默认数据/metadata/PTB路径与原B7一致；可用`--data-root`、`--metadata`、`--ptb-root`显式指定。
一张空闲卡上串行两组时将两个gpu参数设成同一个编号，默认每卡一个进程即自动排队。
仅先做M4的示例：

```bash
python -u scripts/run_b7_m45.py --models M4 --gpu-m4 0 --output results/B7-M4-only
```

Ctrl+b松开再d离开tmux。普通终端查看**新分支、新目录**：

```bash
cd /home/qht/huawei_B7_M45
python scripts/status_b7_m45.py --output results/B7-M4-M5
tail -n 10 -f results/B7-M4-M5/logs/M4_P.log
```

顶层`pipeline_status.json`统一记录M4_P/M5_P等八个阶段，日志统一在顶层logs，不需要切换旧恢复日志。
权重分别保存在`M4_seed42/P`、`M4_seed42/A`等目录。`success:false`在所有阶段完成前正常；
实际`failed`以这个新总控和相应新日志为准。
